# Программа исследования

[English](../en/EXPERIMENT.md) | Русский

Работа отвечает на один вопрос: **какой ценой в полосе и задержке покупается стойкость к анализу
трафика в трёхузловой цепочке с постоянным размером ячейки, и где эта стойкость перестаёт
работать**. Остальное подчинено ответу на него.

Каждый прогон воспроизводим: в отчёт пишутся конфигурация, зерно генератора, версия кода и время.
Результаты в artifacts/, графики строятся из тех же файлов.

Реальные клиенты запускаются в несвязанные моменты, поэтому на стенде расписание каждого клиента
получает случайную фазу из зерна прогона. Клиенты, запущенные подряд, тикали бы почти в одной
фазе и давали атаке ничьи, которых в настоящей сети нет. Окно наблюдения тоже открывается в
случайный момент относительно расписаний: иначе последний запущенный клиент тикал бы в такт окнам.

Зёрна: из базового зерна серии выводится зерно каждого повтора, из него отдельные потоки для фаз
клиентов и для интервалов каждого потока (splitmix64). Соседние повторы и потоки не делят
случайных последовательностей. Фазы часов узлов берутся не из зерна, а из генератора самого
узла, как в настоящем развёртывании. В каждой строке отчёта записаны конфигурация, зёрна,
ревизия кода и загрузка хоста до и после прогона.

## Модели нарушителя

Обозначения используются во всех таблицах результатов.

| Код | Нарушитель | Что видит и может |
|---|---|---|
| П1 | Пассивный на обоих плечах | временные метки и размеры пакетов на участках клиент-первый узел и последний узел-получатель |
| П2 | Пассивный на одном плече | то же, но только на входе цепочки |
| П3 | Активный сетевой | задерживает, дублирует и отбрасывает ячейки, встраивает временную метку в поток |
| П4 | Компрометация узлов | полный доступ к одному или двум узлам из трёх, включая память процесса |
| П5 | Локальный на устройстве | доступ к памяти и диску узла или клиента во время работы и после |
| П6 | Локальный с историей | несколько снимков файла контейнера в разные моменты времени |

Нарушитель знает устройство системы и исходный код. Стойкость держится на ключах и статистической
неразличимости, а не на секретности реализации.

## Метрики

### Связывание отправителя и получателя

| Метрика | Определение | Зачем нужна |
|---|---|---|
| ROC AUC | площадь под кривой ошибок атаки связывания | сводный показатель, сравним между конфигурациями |
| TPR при FPR 0.01 | доля верно связанных пар при фиксированной доле ложных | атака опасна именно в области малых ложных срабатываний |
| Точность при базовой ставке | доля верных среди положительных решений при реальном числе потоков | защищает от подмены понятий: при тысяче потоков AUC 0.9 для нарушителя почти бесполезна |
| Степень анонимности | отношение энтропии апостериорного распределения отправителей к максимальной | стандартная мера, сравнима с литературой |
| Размер множества анонимности | число кандидатов, неотличимых для нарушителя | наглядно на защите |

### Неразличимость трафика

| Метрика | Определение |
|---|---|
| AUC различителя | классификатор отличает ячейку с сообщением от фоновой, ожидается 0.5 |
| Расстояние Колмогорова-Смирнова | между распределениями межпакетных интервалов реального и фонового потоков |
| Оценка полной вариации | верхняя оценка различимости двух распределений по выборке |

### Цена защиты

| Метрика | Определение |
|---|---|
| Множитель полосы | кадров на канале за окно наблюдения к числу сообщений, переданных клиентам. Считается отдельно для канала клиент-вход и для наблюдаемого канала между узлами, в каждую сторону. Окно открывается, когда потоки начинают слать: установка цепочек и всё, что ушло до неё, не входит. Кадр на границе окна не входит |
| Полезная скорость | байт полезной нагрузки в секунду на клиента |
| Задержка | медиана, 95 и 99 процентили. Стенд измеряет круг: от передачи сообщения клиенту до прихода эха выхода, эхо сопоставляется с сообщением по номеру, а не по порядку |
| Стоимость ячейки | наносекунд процессора и аллокаций на снятие слоя |
| Стоимость сессии | наносекунд на согласование ключа, по наборам примитивов |

### Гигиена ключевого материала

| Метрика | Определение |
|---|---|
| Доля успешных извлечений | в какой доле из N попыток ключ найден в дампе |
| Окно жизни ключа | время от конца сессии до момента, когда ключ перестаёт находиться в памяти |
| Доля расшифрованного при краже долговременного ключа | проверка прямой секретности: ноль для записи с провода (каналы на эфемерных ключах); для соседа, сохранившего служебные ячейки, ожидается раскрытие слоёв узла за время его работы |

### Контейнер клиента

| Метрика | Определение |
|---|---|
| Доля пройденных тестов NIST STS | из 15 тестов набора, выборка не менее 100 контейнеров |
| Энтропия на байт | оценка по выборке, ожидается близко к восьми |
| AUC различителя томов | классификатор отличает контейнер с одним томом от контейнера с двумя, ожидается 0.5 |
| Стоимость перебора | параметры Argon2id, время открытия, оценка стоимости подбора пароля заданной энтропии |

## Блоки экспериментов

### Блок 1. Связывание потоков, нарушитель П1

Базовая атака: корреляция числа ячеек в окнах на входе и выходе. Усиленная атака: градиентный
бустинг на признаках окна (число ячеек, дисперсия интервалов, длины пауз, автокорреляция).
Нарушитель обучается на одной выборке и проверяется на другой, разделение по времени.

| Фактор | Уровни |
|---|---|
| Фоновый трафик | нет, 0.5 от полезного, 1.0, 2.0 |
| Размер ячейки | постоянный, переменный по длине сообщения |
| Задержка на узле | нет, отправка по своим часам узла, равномерная, экспоненциальная, пакетирование по k ячеек |
| Число одновременных потоков | 2, 5, 10, 20 |
| Набор примитивов | ГОСТ, X25519 |

План: сначала по одному фактору при прочих базовых, затем полный факторный план на подмножестве
уровней, где ожидается взаимодействие фона и задержек. Главный результат работы это кривая
«множитель полосы против AUC атаки» с доверительными интервалами.

### Блок 2. Активный нарушитель П3, временная метка в потоке

Нарушитель задерживает ячейки на входе по заданному шаблону и ищет этот шаблон на выходе. Атака
сильнее пассивной корреляции и проверяет, помогает ли пакетирование.

| Что меряем | Метрика |
|---|---|
| Обнаружимость метки | AUC детектора метки на выходе |
| Порог стойкости | параметры пакетирования, при которых метка перестаёт обнаруживаться |
| Цена стойкости | прирост задержки доставки, которым это оплачено |
| Устойчивость к потерям | доля отброшенных ячеек, при которой цепочка разрушается |

### Блок 3. Компрометация узлов, нарушитель П4

| Сценарий | Метрика |
|---|---|
| Один узел из трёх | что доступно узлу: соседи, содержимое, доля восстановленного маршрута |
| Первый и последний узлы | доля верно связанных пар, время до связывания |
| Средний и один крайний | то же, для сравнения с предыдущим |
| Подставной узел с валидным сертификатом | доля перехваченных сессий, доля расшифрованного |
| Повтор и подмена ячейки | доля отклонённых, ожидается сто процентов |

Вывод блока: какая доля компрометации цепочки уничтожает свойство и совпадает ли это с
теоретической вероятностью выбора скомпрометированной цепочки.

### Блок 4. Ключевой материал, нарушитель П5

| Сценарий | Метрика |
|---|---|
| Дамп памяти узла во время сессии | доля успешных извлечений, сборка без мер против сборки с mlock и запретом дампов |
| Дамп после завершения сессии | окно жизни ключа в секундах |
| Поиск на диске и в образе | найден или нет |
| Кража долговременного ключа узла | доля расшифрованного из записанного трафика |
| Клиент | найден ли ключ тома в памяти после закрытия контейнера |

### Блок 5. Контейнер клиента, нарушители П5 и П6

| Сценарий | Метрика |
|---|---|
| Статистика шифротекста | NIST STS, энтропия, критерий хи-квадрат |
| Различение одного и двух томов | AUC классификатора на выборке контейнеров |
| Несколько снимков во времени | доля случаев, когда изменения выдают скрытый том |
| Целостность | доля обнаруженных модификаций, ожидается сто процентов |
| Стоимость открытия | время при заданных параметрах Argon2id на целевом железе |

Для П6 результат ожидается отрицательным: против нарушителя со снимками свойство не держится.
Это заявляется как измеренная граница, а не замалчивается.

### Блок 6. Производительность и стоимость примитивов

| Что меряем | Как |
|---|---|
| Согласование ключа | go test -bench, наносекунд на операцию, ГОСТ против X25519 |
| Снятие слоя | наносекунд и аллокаций на ячейку |
| Пропускная способность узла | ячеек в секунду при насыщении, на 1, 2 и 4 ядрах |
| Задержка по хопам | один, два, три узла; p50, p95, p99 |
| Вклад mlock | те же метрики с блокировкой памяти и без |

## Статистика

- Не менее 30 повторов на точку, прогрев отбрасывается.
- Серии гоняются на свободном хосте: параллельная нагрузка сбивает тайминги и занижает AUC
  отдельных прогонов. В таблицах приводится медиана.
- Медиана и доверительный интервал 95 процентов, бутстрэп BCa, 10000 выборок.
- Сравнение конфигураций: критерий Манна-Уитни, уровень 0.05, обязательно с размером эффекта
  (дельта Клиффа). Значимая, но ничтожная разница указывается как таковая.
- Множественные сравнения корректируются методом Холма.
- Перед серией оценивается нужный объём выборки для обнаружения разницы AUC в 0.05 при
  мощности 0.8.
- Классификаторы нарушителя обучаются и проверяются на разных выборках, разделение по времени,
  утечка признаков исключается.

## Угрозы валидности

| Тип | Угроза | Что делаем |
|---|---|---|
| Внутренняя | нарушитель видит идеальные метки времени, которых нет в реальной сети | отдельная серия с сетевым шумом и джиттером |
| Внутренняя | синтетическая нагрузка слишком регулярна | модель трафика с тяжёлыми хвостами, несколько профилей активности |
| Внешняя | стенд на одной машине, задержки моделируются | результаты приводятся как функция заданной задержки, а не как абсолютные числа |
| Конструктная | AUC сам по себе не означает практическую атаку | дополнительно приводится точность при реальной базовой ставке |
| Воспроизводимость | случайность прогонов | фиксированные зерна, конфигурация и версия кода в каждом отчёте |

## Сравнение с аналогами

Таблица по одинаковым признакам: Tor, Session, SimpleX, Briar и эта работа. Признаки: постоянный
размер ячейки, фоновый трафик, состояние на узле, отрицаемость, набор примитивов, опубликованные
оценки задержки. Числа чужих систем берутся из их документации и публикаций, свои измеряются.
Прямое сравнение производительности не проводится: условия разные, это указывается явно.

## Что показываем на защите

1. Живая отправка сообщения через три узла и панель «что видит каждый узел».
2. Наблюдатель: без фонового трафика AUC атаки близка к единице, с фоновым падает к 0.5.
   Система ломается и чинится на глазах комиссии.
3. Кривая «множитель полосы против AUC» с доверительными интервалами.
4. Ключ находится в дампе без мер и не находится с mlock и запретом дампов.
5. Контейнер: один пароль открывает легенду, второй настоящую историю, рядом результаты NIST STS.
6. Таблица стоимости: ГОСТ против X25519, задержка по хопам.
